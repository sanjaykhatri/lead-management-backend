## Prerequisites

Before you begin, ensure you have the following installed:

- **PHP 8.2+** with extensions:
  - `php-mbstring`
  - `php-xml`
  - `php-curl`
  - `php-zip`
  - `php-mysql` or `php-pgsql` (depending on your database)
  - `php-bcmath`
  - `php-gd`
- **Composer** (PHP package manager)
- **MySQL 5.7+** or **MariaDB 10.3+**
- **Node.js 18+** and **npm** (for frontend assets)
- **Git**

### Verify Prerequisites

```bash
# Check PHP version
php -v

# Check Composer
composer --version

# Check MySQL
mysql --version

# Check Node.js
node -v
npm -v
```

## Installation

### Step 1: Clone the Repository

```bash
git clone <repository-url>
cd lead-management-backend
```

### Step 2: Install PHP Dependencies

```bash
composer install
```

This will install all Laravel dependencies and packages including:
- Laravel Framework 12
- Laravel Sanctum (API authentication)
- Stripe PHP SDK
- Pusher PHP SDK
- Twilio Notification Channels (optional)

### Step 3: Install Frontend Assets (Optional)

If you need to compile frontend assets:

```bash
npm install
npm run build
```

### Step 4: Copy Environment File

```bash
cp .env.example .env
```

### Step 5: Generate Application Key

```bash
php artisan key:generate
```

This generates a unique encryption key for your application.

## Environment Configuration

Edit the `.env` file with your configuration. Here are the required and optional variables:

### Required Variables

```env
# Application
APP_NAME="Lead Management System"
APP_ENV=local
APP_KEY=base64:... (generated by key:generate)
APP_DEBUG=true
APP_TIMEZONE=UTC
APP_URL=http://localhost:8000

# Database
DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=lead_management
DB_USERNAME=root
DB_PASSWORD=your_password

# Frontend URL (for CORS)
FRONTEND_URL=http://localhost:3000
```

### Optional but Recommended

```env
# Queue Configuration
QUEUE_CONNECTION=database

# Broadcasting (Pusher)
BROADCAST_DRIVER=pusher
PUSHER_APP_ID=your_app_id
PUSHER_APP_KEY=your_app_key
PUSHER_APP_SECRET=your_app_secret
PUSHER_APP_CLUSTER=ap2

# Stripe (Required for subscription features)
STRIPE_KEY=pk_test_...
STRIPE_SECRET=sk_test_...
STRIPE_WEBHOOK_SECRET=whsec_...
STRIPE_PRICE_ID=price_...

# Twilio (Optional - for SMS notifications)
TWILIO_ENABLED=false
TWILIO_ACCOUNT_SID=your_account_sid
TWILIO_AUTH_TOKEN=your_auth_token
TWILIO_FROM=+1234567890

# Mail Configuration (Optional)
MAIL_MAILER=smtp
MAIL_HOST=smtp.mailtrap.io
MAIL_PORT=2525
MAIL_USERNAME=your_username
MAIL_PASSWORD=your_password
MAIL_ENCRYPTION=tls
MAIL_FROM_ADDRESS=noreply@example.com
MAIL_FROM_NAME="${APP_NAME}"
```

### Environment-Specific Notes

**Development:**
- Set `APP_DEBUG=true`
- Use `QUEUE_CONNECTION=sync` for immediate processing (no queue worker needed)
- Use Stripe test keys

**Production:**
- Set `APP_DEBUG=false`
- Use `QUEUE_CONNECTION=database` or `redis`
- Use Stripe live keys
- Set secure passwords
- Use proper mail configuration

## Database Setup

### Step 1: Create Database

```bash
# Login to MySQL
mysql -u root -p

# Create database
CREATE DATABASE lead_management CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

# Create user (optional, recommended for production)
CREATE USER 'lead_user'@'localhost' IDENTIFIED BY 'secure_password';
GRANT ALL PRIVILEGES ON lead_management.* TO 'lead_user'@'localhost';
FLUSH PRIVILEGES;

# Exit MySQL
EXIT;
```

### Step 2: Configure Database Connection

Update `.env` with your database credentials:

```env
DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=lead_management
DB_USERNAME=root
DB_PASSWORD=your_password
```

### Step 3: Run Migrations

```bash
php artisan migrate
```

This will create all necessary tables:
- `users` - Admin users
- `service_providers` - Service provider accounts
- `locations` - Physical locations
- `leads` - Customer leads
- `lead_notes` - Notes on leads
- `location_service_provider` - Location-provider relationships
- `stripe_subscriptions` - Subscription tracking
- `subscription_plans` - Available plans
- `subscription_history` - Subscription history
- `notifications` - System notifications
- `settings` - Application settings
- `jobs` - Queue jobs
- `failed_jobs` - Failed queue jobs
- `personal_access_tokens` - API tokens
- `activity_logs` - Activity tracking
- `provider_performance_metrics` - Provider metrics
- `cache` - Cache table

### Step 4: Create Admin User

```bash
php artisan tinker
```

Then run:

```php
use App\Models\User;
use Illuminate\Support\Facades\Hash;

$user = User::create([
    'name' => 'Admin',
    'email' => 'admin@example.com',
    'password' => Hash::make('password'),
    'role' => 'super_admin'
]);

exit;
```

**Important:** Change these credentials in production!

### Step 5: Create Queue Tables (if using database queue)

```bash
php artisan queue:table
php artisan migrate
```

## Queue Setup

The application uses Laravel queues for processing background jobs (notifications, broadcasting, etc.).

### Development Setup

For development, you can use synchronous processing:

```env
QUEUE_CONNECTION=sync
```

This processes jobs immediately without a queue worker.

### Production Setup

For production, use database or Redis queues:

#### Option 1: Database Queue (Recommended for shared hosting)

```env
QUEUE_CONNECTION=database
```

Then run the queue worker:

```bash
php artisan queue:work --tries=3 --timeout=60
```

#### Option 2: Redis Queue (Recommended for VPS/dedicated servers)

1. Install Redis:
```bash
# Ubuntu/Debian
sudo apt-get install redis-server

# macOS
brew install redis
```

2. Update `.env`:
```env
QUEUE_CONNECTION=redis
REDIS_HOST=127.0.0.1
REDIS_PASSWORD=null
REDIS_PORT=6379
```

3. Run queue worker:
```bash
php artisan queue:work redis --tries=3 --timeout=60
```

### Running Queue Worker

**Development:**
Run in a separate terminal:
```bash
php artisan queue:work
```

**Production:**
Use a process manager like Supervisor or systemd (see [Cron Jobs Setup](#cron-jobs-setup) section).

## Broadcasting Setup (Pusher)

3. Create a new app
4. Note your credentials:

```env
BROADCAST_DRIVER=pusher
PUSHER_APP_ID=your_app_id
PUSHER_APP_KEY=your_app_key
PUSHER_APP_SECRET=your_app_secret
```

1. Login as admin

4. Test connection

### Step 4: Test Broadcasting

1. Start the queue worker (if using queues)
2. Create a lead or update status
3. Check browser console for Pusher connection
4. Verify notifications appear in real-time

**Note:** Broadcasting requires the queue worker to be running if `QUEUE_CONNECTION` is not `sync`.

## Stripe Setup

Stripe is used for subscription management.

### Step 1: Create Stripe Account

1. Go to [stripe.com](https://stripe.com)
2. Create an account
3. Get your API keys from the Dashboard

### Step 2: Create Product and Price

1. Go to Products in Stripe Dashboard
2. Create a new product
3. Add a price (recurring subscription)
4. Copy the Price ID (starts with `price_`)

### Step 3: Configure Webhook

1. Go to Developers > Webhooks in Stripe Dashboard
2. Add endpoint: `https://yourdomain.com/api/stripe/webhook`
3. Select events:
   - `customer.subscription.created`
   - `customer.subscription.updated`
   - `customer.subscription.deleted`
   - `checkout.session.completed`
   - `invoice.payment_succeeded`
   - `invoice.payment_failed`
4. Copy the webhook signing secret (starts with `whsec_`)

### Step 4: Configure Environment

```env
STRIPE_KEY=pk_test_... (or pk_live_... for production)
STRIPE_SECRET=sk_test_... (or sk_live_... for production)
STRIPE_WEBHOOK_SECRET=whsec_...
STRIPE_PRICE_ID=price_...
```

### Step 5: Test Webhook Locally (Development)

Use Stripe CLI:

```bash
# Install Stripe CLI
# macOS
brew install stripe/stripe-cli/stripe

# Login
stripe login

# Forward webhooks to local server
stripe listen --forward-to localhost:8000/api/stripe/webhook
```

This will give you a webhook secret to use in `.env` for local testing.

## Cron Jobs Setup

The application uses Laravel's scheduler to run queue workers and other scheduled tasks.

### Local Development

Run the scheduler manually:

```bash
php artisan schedule:run
```

Or use Laravel's built-in scheduler (runs every minute):

```bash
php artisan schedule:work
```

### Shared Hosting (cPanel)

1. Log in to cPanel
2. Go to **Cron Jobs**
3. Add a new cron job:

**Option 1: Using Laravel Scheduler (Recommended)**
```
Minute: *
Hour: *
Day: *
Month: *
Weekday: *
Command: /usr/bin/php /home/username/public_html/lead-management-backend/artisan schedule:run
```

**Option 2: Using cron.php Script**
```
Command: /usr/bin/php /home/username/public_html/lead-management-backend/cron.php
```

**Option 3: Direct Queue Worker**
```
Command: /usr/bin/php /home/username/public_html/lead-management-backend/artisan queue:work --stop-when-empty --tries=3 --timeout=60 --max-time=60
```

**Important:** Replace `/home/username/public_html/lead-management-backend` with your actual project path.

### Finding Your PHP Path

Create a `phpinfo.php` file:

```php
<?php phpinfo();
```

Visit it in your browser to find the PHP path, or check cPanel > Select PHP Version.

Common PHP paths:
- `/usr/bin/php`
- `/usr/local/bin/php`
- `/opt/cpanel/ea-php81/root/usr/bin/php` (cPanel EasyApache)

### VPS/Dedicated Server (Supervisor)

Create `/etc/supervisor/conf.d/laravel-worker.conf`:

```ini
[program:laravel-worker]
process_name=%(program_name)s_%(process_num)02d
command=php /path/to/lead-management-backend/artisan queue:work --sleep=3 --tries=3 --max-time=3600
autostart=true
autorestart=true
stopasgroup=true
killasgroup=true
user=www-data
numprocs=2
redirect_stderr=true
stdout_logfile=/path/to/lead-management-backend/storage/logs/worker.log
stopwaitsecs=3600
```

Then:

```bash
sudo supervisorctl reread
sudo supervisorctl update
sudo supervisorctl start laravel-worker:*
```

## Troubleshooting

### Common Issues

#### 1. Database Connection Error

**Error:** `SQLSTATE[HY000] [2002] Connection refused`

**Solution:**
- Verify MySQL is running: `sudo service mysql status`
- Check database credentials in `.env`
- Verify database exists: `mysql -u root -p -e "SHOW DATABASES;"`
- Check firewall settings

#### 2. Migration Errors

**Error:** Foreign key constraint errors

**Solution:**
- Run migrations in order: `php artisan migrate:fresh`
- Check migration files are in correct order
- Verify foreign key relationships

#### 3. Queue Not Processing

**Error:** Jobs not being processed

**Solution:**
- Verify queue worker is running: `ps aux | grep "queue:work"`
- Check queue connection: `QUEUE_CONNECTION` in `.env`
- Check jobs table exists: `php artisan migrate`
- View failed jobs: `php artisan queue:failed`

#### 4. Pusher Not Working

**Error:** No real-time notifications

**Solution:**
- Verify Pusher credentials in `.env` or database settings
- Check queue worker is running (broadcasting uses queues)
- Check browser console for Pusher connection errors
- Verify `BROADCAST_DRIVER=pusher` in `.env`
- Test Pusher connection in admin settings

#### 5. Stripe Webhook Not Working

**Error:** Subscriptions not updating

**Solution:**
- Verify webhook secret in `.env`
- Check webhook endpoint is accessible
- Verify webhook events are selected in Stripe Dashboard
- Check Laravel logs: `tail -f storage/logs/laravel.log`
- Test with Stripe CLI locally

#### 6. Permission Errors

**Error:** `Permission denied` or `Cannot write to storage`

**Solution:**
```bash
# Set proper permissions
chmod -R 775 storage bootstrap/cache
chown -R www-data:www-data storage bootstrap/cache
```

#### 7. CORS Errors

**Error:** CORS policy blocking requests

**Solution:**
- Verify `FRONTEND_URL` in `.env` matches your frontend URL
- Check `config/cors.php` configuration
- Clear config cache: `php artisan config:clear`

#### 8. Token Authentication Issues

**Error:** `Unauthenticated` or token errors

**Solution:**
- Verify token is sent in `Authorization: Bearer {token}` header
- Check token exists in `personal_access_tokens` table
- Verify Sanctum is configured correctly
- Clear cache: `php artisan config:clear && php artisan cache:clear`
